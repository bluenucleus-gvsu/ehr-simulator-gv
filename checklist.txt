1) **App/simulation rendering overview**

- The simulation UI is a **Next.js App Router** area rooted at `ehr-simulator/src/app/simulation/**`, with the main experience under `ehr-simulator/src/app/simulation/[sessionId]/chart/**`.
- Current state: UI structure is fairly complete (shell, tabs, overview cards, Labs, Orders, MAR, Notes, FlexSheets), but **rendering is overwhelmingly mock/template-driven**.
- Real backend data exists and is already authored via case builder:
  - `cases`, `case_family_history`, `case_safety_alerts`
  - `clinical_documents`
  - `orders`
  - `lab_results`, `imaging_reports`, `microbiology_reports`
  - `documentation_results`
  - `medication_administrations`
- The main reusable read loader exists: `ehr-simulator/src/actions/case_builder/getCase.ts` (`getCaseBundle(caseId)`), but simulation pages currently do not consume it.
- Biggest foundation issue before “real rendering”: route identity mismatch (`section_assignments.id` vs `case_sessions.id` vs route param name `sessionId`).

4) **Route/data-flow foundation**

## Canonical flow to implement

1. **Entry route / session list**
   - Keep student launch from `src/app/user/profile/[id]/page.tsx` + `AssignedCaseCard`.
   - URL currently gets `id = section_assignments.id` from `get_user_courses`.

2. **Canonical URL identity (for now)**
   - Use `section_assignments.id` as canonical route param for `/simulation/[sessionId]/...` in this backup repo, because that is what live student links already emit.

3. **Resolve URL → simulation context**
   - Add one server-side resolver (new action/loader):
     - input: `sectionAssignmentId` (route param)
     - output: `{ sectionAssignment, caseSession?, caseId, simTime, presimTime, studentGroupContext }`
   - Minimum required for rendering: `caseId`.
   - Optional/next: validate current user belongs to a group/session for this assignment.

4. **Fetch rendering bundle**
   - call `getCaseBundle(caseId)` from `src/actions/case_builder/getCase.ts`.
   - This provides all main case content surfaces in one response.

5. **Distribute into chart tree**
   - In `src/app/simulation/[sessionId]/chart/layout.tsx` (or a wrapper at chart root), fetch resolver + case bundle server-side.
   - Pass down via:
     - context provider (recommended for many tabs), or
     - per-page server props wrappers.
   - Keep all existing UI layout/components; only swap data source.

6. **Surface consumption map**
   - Sidebar + demographics + active problems + visitors + family history + alerts: from `caseRow`, `familyHistory`, `safetyAlerts`.
   - Orders + recurring + nutrition: from `orders`.
   - Notes: from `clinicalDocuments`.
   - Labs + selected labs: from `labResults` + `imagingReports` + `microbiologyReports`.
   - Charting + vitals + I/O: from `documentationResults`.
   - MAR + snapshot: from `medicationAdministrations` (+ med order source strategy).

## Identity mismatch explicitly

- `section_assignments.id`: used for **assigned launch**.
- `case_sessions.id`: used in **completed list**.
- `case_id`: required by `getCaseBundle`.

**What must be solved before other rendering work:** stable `routeId -> case_id` resolution.  
Without this, no “real rendering” is trustworthy.
